# Pipeline 监控与报告

本功能采集指定 GitLab 项目的流水线及 Job 执行记录，按任务配置发送完成卡片，并可发布长期筛选报告。配置项见 [配置说明](configuration.md)，新建站点源码见 [流水线报告模板](../templates/pipeline-pages/README.md)。本文描述行为契约，不记录某台机器的任务、部署地址或验收历史。

## 开关与目标

- `PIPELINE_MONITOR_ENABLED` 默认 `false`。启用时要求 GitLab 功能、认证及所需读取权限，提供 `/pipeline` 命令、采集和卡片投递。
- `PIPELINE_PUBLISH_ENABLED` 默认 `false`，独立控制后台发布。关闭时不要求报告仓库，可正常采集、保存记录并发卡片。
- 开启发布须同时开启监控，并显式填写 `PIPELINE_PAGES_REPO_URL`，地址没有默认值或内部兜底，只接受 SSH。`PIPELINE_PAGES_BRANCH` 默认 `main`。例如使用 `git@gitlab.example.com:team/monitor-site.git`，实际目标由部署者设置。
- API 主机和项目由 SSH 目标推导；自定义 SSH 端口只用于 Git，Web/API 使用该主机的 HTTPS。报告仓库可以与采集项目位于不同主机。本地工作区为 `.project/<仓库名>/`，须提前克隆并核对 origin、分支和工作区状态；发布器不会自动克隆、初始化或覆盖站点。
- 配置只启用能力；具体监控范围、接收会话和发布内容仍以主人确认的任务为准。已有发布记录绑定目标身份，包括主机、完整项目、SSH 端口和分支。变更目标不会自动迁移历史或复用旧在途提交；存在旧发布状态时须单独处理迁移。旧历史缺少 `pages_target` 绑定元数据时，不猜测原目标，发布会要求先核实原仓库并迁移绑定，不能自动绑定到新配置目标。

## 创建与管理

`/pipeline creat`（兼容 `create`）建立独立话题，按模板逐项填写项目、分支、间隔、历史范围、失败范围和接收会话。默认间隔 10 分钟，包含失败与 Tag，使用默认分支、近 7 天补采并汇报主人。间隔支持 1～1440 分钟；历史日期按配置时区的执行完成时间解释，不限制天数。多分支可填写 `develop,release/example`，不要在字段值中混入解释文字。

修改配置先展示差异并验证远端。只有最新预览成功送达后，准确回复“确认创建”或“确认修改”才执行；普通“好的”“同意”不替代此确认。重复监控范围先展示重复提示，收到后才可回复“确认独立创建”。更换采集仓库需要另建任务，未知字段会提示按模板填写。

| 命令 | 行为 |
| --- | --- |
| `/pipeline list [页码]` | 查看本机任务及远端缓存，每页 10 条；其他来源任务仅供查看，不自动接管 |
| `/pipeline status [编号]` | 查看状态、采集缺口、发送及发布进度；任务话题中可省略编号 |
| `/pipeline start [编号]` | 启动或恢复已确认任务，仍执行原有归属与站点审查检查 |
| `/pipeline stop [编号]` | 暂停后续采集和通知，保留历史 |
| `/pipeline delete [编号]` | 在所属话题展示影响，准确回复“确认删除”后停止并处理下架 |

收件人为空时由 bot 回复任务话题。指定其他接收会话时核实主人身份、会话和访问范围，使用本人身份发送，不发探测消息。单聊称呼遵守 [AGENTS.md](../AGENTS.md)；群聊使用“你好，各位”，代发署名读取当前配置。身份不符不切换其他账号发送。

## 采集、重试与时间口径

本地 SQLite 保存草稿、任务配置、观察、执行历史、发送队列和不可变快照。公开站点只含允许展示的字段，不含会话 ID、游标、凭证或原始日志。所有日期理解、历史窗口、卡片与统计展示使用 `TIMEZONE`，默认 `Asia/Shanghai`；新站点 manifest 保存 `timezone`，缺少该字段的旧数据使用 `Asia/Shanghai`。

一次 Pipeline 重试可能保留原 Pipeline ID；用实际 Job ID 识别各次尝试，不以 Job 名称或提交 SHA 去重。历史无法可靠还原时保留已知尝试并标注不完整，不伪造执行次数。任务配置与计算算法分别保存版本，便于隔离可比样本。

| 指标 | 口径 |
| --- | --- |
| 有效执行 | 本次 Job 起止区间并集，包含同仓库子流水线；并行区间只计一次 |
| 完整历时 | 本次最早 Job 开始至最后 Job 结束，开始前排队独立展示 |
| Pipeline 排队 | 保留 GitLab 原始 `queued_duration` |
| Job 排队 | 单独展示累计与最长排队，累计值不等于墙钟等待 |
| 未知与零值 | 缺失值为 `null`，不能当作零；已知零时长是有效样本 |

MR 按目标分支匹配，Tag 单独控制。同仓库子流水线归父记录汇报，跨仓下游只保留链接。父记录首次观察到稳定终态后最多再等一个监控间隔；子任务仍未结束时先保存不完整结果并通知，整体执行耗时保持未知，已知 Job 数据保留。晚到数据只补全原记录及报告，不再发一张卡片；新的重试尝试作为独立执行记录。

分页或列表请求失败不推进已确认水位。单个 Pipeline 失败保存为采集缺口，其他记录继续处理；缺口独立重试并在状态中展示。扫描有页数、时长和图遍历上限，达到上限保留分页进度或缺口，不把截断数据标为完整。重复引用子图使用当前轮缓存，真正循环保留为缺口。

## 卡片、失败原因与交互

每次新完成执行、每个收件会话发送一张结果卡片，合并耗时、告警和证据。取消或跳过只保存状态；是否通知失败按任务配置。首次历史补采不逐条通知旧执行，配置发布且部署成功后才发送首次报告链接；恢复补采同样不重发旧完成卡片。关闭发布时不生成已上线报告的说法。

卡片包括阶段时间线、可选择阶段的 Job 时间线、耗时对比和折叠明细。横轴以本次最早已知开始时间为原点，条段使用真实起止；同阶段重叠区间合并，中间空档不连线，子 Pipeline 的同名阶段保持独立。阶段顺序优先采用已核实的 GitLab 元数据；缺失时提示顺序未核实，并按已知 Job 信息排列。缺少起止时间不倒推条形，零时长仍视为有效。内容超限会明确裁剪并在可用时提供完整报告入口。

告警按同 Tag、分支、来源、状态、执行类型、配置版本和算法版本的近 7 天可比记录计算。默认单 Job 排队超过 600 秒、执行超过 1800 秒；明显变慢需有效样本至少 10 个、中位数增加至少 50% 且至少 300 秒。阈值可在任务话题修改并确认。卡片历史中位数与长期报告算术平均为独立口径，不能混用。

失败原因采用 GitLab 原因及有限日志中的确定规则，并保留证据链接；规则分类不等于模型核实根因。日志读取限制并发、字节数及时间，忽略 Range 的服务器也不能导致整份缓冲；原始 trace 不入库、不外发。晚到分析仅更新报告。

阶段切换只更新已登记的原卡片，不调用模型、新增通知、启动监控或触发发布。校验接收范围、动作、有效选项、任务状态及回调时效，时间戳和事件 ID 去重。主人私聊仅接受主人操作；已授权群会话成员共享同一选择结果。暂停任务可查看历史，删除中或已删除任务不能交互；转发后未登记的副本不处理。

回调中的 `card_content` 是 CLI 补充读取的内容，允许缺失或为空，不作为授权依据。阶段视图始终根据服务已登记的卡片快照和执行数据生成，不采用回调携带的任意卡片正文；缺少附加正文不改变其他归属、身份和时效校验。

切换时先清空旧 Job 内容并显示等待状态，再展示新数据；网络和平台更新存在延迟。失败不盲目重放旧回调，可重新选择产生新请求。回调 Token 只经 stdin 传入接口，不写入命令参数、日志或数据库。真实客户端点击、后台回传配置和实际更新需在部署环境验证，不能用消费者就绪或单元测试代替。

## 投递不确定性

发送前持久保存 `sending` 状态；异常或重启导致结果不确定时转为 `uncertain`，保留已确认收件进度，不盲目重发。一个会话失败不会使已成功会话再次收到同一执行。身份校验失败保留队列，运行故障通知主人任务话题；需先核查实际飞书消息再决定恢复。

## 长期统计报告

报告以跨次平均耗时为首要视图，单次详情作为下一层。可按日期窗口、成功或失败、分支、触发类型、重试、失败原因和告警筛选。Pipeline 按分支与触发类型分组，MR 使用目标分支；Tag、执行类型、配置版本、算法版本保持隔离。Job 按项目、阶段、完整名称和 Job 状态分组，并用实际 Job ID 去重。

均值是有效执行样本的算术平均，不平均每日均值；负值、非数值和缺失不计入，已知零值计入。展示有效样本数与缺失情况，少于 5 个有效样本明确提示小样本。未知 Pipeline 时长不妨碍查看已知 Job。每日趋势按配置时区的完成日期汇总，无有效样本的日期留空；并行 Job 均值不能相加当作 Pipeline 耗时。

选定日期范围中任一月份文件读取失败会明确报错，不用部分数据假装全量。页面数据通过文本节点显示，链接仅接受无凭证 HTTPS；静态页面不依赖 CDN。单次详情保留阶段及 Job 共用时间轴、证据和原始链接。

## 发布快照与站点审查

发布独立于采集。每批生成不可变任务快照，已有在途提交或 CI 时把新数据合并到下一批。快照绑定任务版本，只有完成部署核实才推进确认状态；push 成功不等于部署成功。

跨进程文件锁串行报告仓库写入，读写前 fetch，主工作区必须干净且无未知本地提交。生成提交使用隔离的临时 worktree，只正常快进 push，不强推。各任务生成目录归属独立，检测到外部修改时停止受影响发布，保留其他修改。远端前进后重新构造增量并退避，内容冲突不自动合并。

站点改版后，恢复自动监控前先核实报告工作区无未提交改动、处于 `PIPELINE_PAGES_BRANCH` 指定的分支并可正常快进。保留开发分支及本地修改，不强制重置或覆盖。分支不匹配、未审阅改动、未知本地提交、缺少 Pages CI 和共享生成器变化均显示固定的可操作提示，其他未经安全处理的异常不展示原始内容。

共享站点源码或 CI 变化会阻止发布。须在任务话题回复“审查发布变更”，取得具体 diff、固定版本链接和摘要；该预览送达后回复“确认发布变更 <完整摘要>”。接受前再次 fetch 并核对共享文件树，变化后重新审阅。`start` 和开关配置均不绕过此门禁。

CI 失败保留未部署版本并退避；排队或未知持续过久会显示受阻并通知主人，不制造更多 CI。须核实 Pages 作业、对应环境部署 SHA、有效根部署与创建时间，不能证明部署时保持待核实，不发送首次已发布报告链接。

采集成功只清除采集及分页变化相关错误，不清除发布失败、发布等待超时或投递不确定提示。只有实际部署核实成功后，才清除“报告发布失败”和“Pages 发布等待超时”；同时按来源清理对应的 API 错误信息，保留尚未恢复的其他阶段诊断。兼容旧状态时依据已有错误类型识别归属，不用一次成功操作代替其他阶段的恢复确认。

暂停发布只更新 manifest 状态，已发布月份数据保持原样。`published_revision` 表示状态快照确认，`published_data_revision` 独立表示数据确认；暂停不推进数据确认，恢复后包含积压记录。

删除先停止采集与通知、清除未发卡片，在途旧快照结束后再发布下架版本。只有能证明从未尝试发布且无在途痕迹时才直接清理本地历史；其余须核实报告下架后清理，保留最小任务标识和结果，不重写 Git 历史或备份。发布关闭或远端文件暂时不存在，均不单独证明从未发布。

## 部署与验证

模板与已部署站点独立维护，不自动相互覆盖。部署者配置 Runner、分支保护、Pages 权限和并发部署策略，确认站点支持当前公开数据契约。发布端与构建端分别执行嵌套字段白名单，未知字段不进入产物，已知字段类型错误应使构建失败。

项目测试使用临时仓库与模拟接口，不需要真实发布目标：

```bash
python3 -m unittest discover -s tests
```

修改公开数据契约后，另用 `PIPELINE_PAGES_TEST_ROOT` 指向已核实的站点工作区，运行兼容性检查；站点自身测试与构建命令按目标仓库 README 执行。未设置该路径时跨仓库检查可明确跳过，无效路径不能当作通过。配置与代码检查完成后，再验证真实权限、卡片客户端渲染、回调和部署；这些操作的范围以当前任务授权为准。
